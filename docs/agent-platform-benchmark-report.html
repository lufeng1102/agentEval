对当前业界与开源界 Agent / LLM 应用测试评测平台进行调研，并与 AgentEval 的本地评测、CI gate、trace replay、regression mining、promotion governance 与 RSI 安全治理能力对标。

核心结论

AgentEval 不应只做另一个 metric runner，而应定位为面向 agentic / self-improving AI 的本地优先评测与发布治理平台。

最大差距

Hosted dashboard、团队协作、trace UI、OpenInference/OTLP 互操作、广泛生态 instrumentation 和 production feedback loop。

1. Executive Summary

当前业界 Agent / LLM 应用测试评测生态大致形成三类主流能力中心：

  1. 本地/CI 评测框架：DeepEval、promptfoo、Inspect AI、Ragas、OpenAI Evals。
  2. Trace / Observability / Instrumentation 平台：OpenInference、Phoenix/Arize、LangSmith、Langfuse、Braintrust。
  3. 托管协作 / 生产监控 / 反馈闭环平台：LangSmith、Phoenix/Arize、Braintrust、Langfuse Cloud、Confident AI、Humanloop、W&B Weave 等。
AgentEval 的相对优势：将 YAML dataset/config、agent adapters、traces、evaluators、reports、CI thresholds、failure mining/regression、promotion gates、production trace replay 与 RSI governance 放在一个 Python 本地优先、CI 友好、artifact-first 的工作流中。

尤其是 RSI / self-improvement governance 是主流平台中相对少见的差异化方向。多数平台覆盖通用 LLM eval、RAG eval、red teaming、observability，但很少把 self-modification、eval integrity、anti-gaming、holdout、capability frontier、memory pollution、action risk、evolution loop 等治理维度作为一等公民。

主要差距集中在 hosted dashboard / team collaboration、production feedback loop、广泛生态 adapter / instrumentation、OpenTelemetry / OpenInference 深度兼容、trace UI / trajectory viewer、dataset UI / annotation workflow、商业托管能力与官方 benchmark / 示例生态。

4. 关键发现

4.1 本地/CI eval 框架已经成熟，AgentEval 不能只做 metric runner

DeepEval、promptfoo、OpenAI Evals 已经覆盖 test case / dataset、metric / assertion、model-graded eval、CI/CD、threshold pass/fail、多 provider 或自定义 completion function。

AgentEval 应继续强化从 eval runner 到 release governance engine 的路径：baseline/candidate compare、failure mining、regression generation、promotion gates、production trace replay 与 RSI governance。

4.2 Inspect AI 是 agent/tool/multi-agent 维度最直接的开源对标

Inspect AI 的强项包括 Task(dataset/solver/scorer)、tools、sandbox、MCP、multi-agent primitives、外部 CLI agent bridge 与 Inspect View local UI。

AgentEval 当前具备 trajectory evaluator、tool_output evaluator、span evaluator、environment evaluators、Claude Code adapter、LangChain adapter MVP 与 trace replay，但在 tool sandbox 一体化、MCP tools、外部 CLI agent bridge、trajectory viewer、built-in benchmark library 上仍有差距。

4.3 OpenTelemetry / OpenInference 是 trace 互操作主线

OpenInference/Phoenix 的优势在于基于 OpenTelemetry、支持 OTLP traces、具备 LLM/retrieval/tool/API semantic conventions 与生态 integration。

AgentEval 已有 trace import/replay、production trace normalization、Langfuse/Phoenix-style import、P3 export skeleton、SDK instrumentation skeleton。下一步关键是对齐 OpenInference span attributes、支持 OTLP import/export，并增强 Phoenix/Langfuse/Braintrust conformance tests。

4.4 RAG/LLM-as-judge 不宜成为唯一卖点

DeepEval、Ragas、Phoenix eval、LangSmith eval、promptfoo model-graded assertions 都已经覆盖大量 RAG / judge metrics。

AgentEval 应强调 expected schema 明确、judge config 可版本化、judge output 可缓存/审计、trace replay 可复现、promotion gate 可执行、failures 可转 regression、RSI/security context 可治理。

4.5 Hosted/协作/生产 feedback 是最大产品差距

成熟商业平台常见能力包括 hosted dashboard、workspace/project、dataset UI、experiment lineage、prompt/version management、annotation/review queue、online eval、feedback loop、alerting、RBAC、trace search、retention/compliance。

AgentEval 当前本地 CLI 和 artifact 很强，但 hosted/dashboard/alerts/workspace 仍主要是 skeleton 或 roadmap。

4.6 RSI/self-improvement governance 是最强差异化机会

AgentEval 的 RSI governance 覆盖 self-modification review、safety envelope、eval integrity、anti-gaming、holdout analysis、capability frontier、attribution、evolution loop metrics、memory pollution、action risk 与 RSI redteam。

推荐包装：AgentEval is an evaluation and release governance platform for agentic and self-improving AI systems.

6. 推荐产品定位

推荐定位：AgentEval = 本地优先的 agent evaluation + release governance 平台，面向 Claude/LLM/RSI/self-improving agents。

关键词：

  • local-first
  • CI-native
  • artifact-first
  • trace replay
  • regression mining
  • promotion governance
  • RSI safety
  • ecosystem adapters
  • hosted optional
不建议定位：不要只定位为 RAG metric framework、LLM-as-judge wrapper、observability dashboard、prompt testing CLI 或 generic LangChain tracing tool。这些方向已有强势平台，且 AgentEval 当前优势不在这里。

7. 路线建议

P0：夯实本地 CI + 治理闭环

  1. 修复 RSI 风险字段归一化问题：memory/evolution_loop risk fields、redteam minefield schema、canary rank。
  2. 强化 adapter contract：conformance suite；static/anthropic/claude_code/langchain 全部跑 conformance；adapter metadata 标准化。
  3. 强化 CI examples：GitHub Actions、baseline/candidate compare、promotion policy gate、failure-to-regression 自动生成。
  4. 强化 docs：AgentEval vs DeepEval/promptfoo/Inspect/Ragas、RSI governance quickstart、production trace replay quickstart、LangChain adapter quickstart。
  5. 建立 RSI demo benchmark：eval tampering、holdout leakage、memory poisoning、action risk、self-modification regression。

P1：生态互操作与 agent trajectory

  1. OpenInference / OTLP 对齐：import/export conformance tests、span kind/attributes mapping、OTLP ingest/export MVP。
  2. LangChain adapter 增强：callback handler、LangGraph、retriever spans、memory metadata、tool error mapping。
  3. Inspect AI 对标能力：MCP tool adapter、sandboxed tool execution、external CLI agent adapters、multi-agent transcript、trajectory viewer data model。
  4. Export/import 增强：Langfuse、Phoenix、Braintrust、LangSmith-compatible traces。
  5. Dashboard MVP：run list、case detail、trace viewer、evaluator result table、compare view、RSI governance view。

P2：Hosted / Collaboration / Production feedback

  1. Hosted API：run ingestion、artifact storage、project/workspace、API tokens。
  2. Team workspace：users、roles、RBAC、shared datasets/configs/policies、audit logs。
  3. Production feedback loop：trace search、feedback ingestion、negative feedback mining、review queue、feedback-to-regression。
  4. Alerts：webhook、Slack/email、governance alerts、regression alerts、latency/cost alerts。
  5. Annotation / review UX：human labels、disagreement analysis、judge calibration、review coverage。
  6. Enterprise readiness：retention、self-host、VPC/on-prem、SSO、compliance。

9. 结论

AgentEval 当前不应该走“再做一个 LLM eval metric framework”的路线。

更有机会的路线：AgentEval = 面向 agentic / self-improving AI 的本地优先评测与发布治理平台。

短期应强化本地 CI gate、regression mining、promotion policy、RSI governance、trace replay、LangChain/Claude Code adapter、OpenInference/Phoenix/Langfuse/Braintrust 互操作。

中长期再补 hosted dashboard、team workspace、production feedback、annotation/review、alerts、enterprise/self-hosted deployment。

这样 AgentEval 才能避开 DeepEval/Ragas/promptfoo 在通用指标/声明式测试上的红海，也避开 LangSmith/Phoenix/Langfuse 在纯 observability 上的强势区间，形成围绕 self-improving agents release governance 的差异化护城河。
